# Yuru でレビューを依頼する

現在の worktree に新しいレビューセッションを作る。別の worktree は作らない。

## レビューへの入力

レビュワーに渡すのは、現在の要件と変更対象だけにする。

- 要件は、要件ドキュメントのパスと該当見出しだけを示す。内容を要約しない。実装中に要件が
  明示的に変更された場合だけ、その変更内容を文脈が伝わるよう簡潔に要約する。不明な点は
  推測せずユーザーに確認する。
- 実装中の会話、実装理由、採用しなかった案、実装者の自己評価、疑っている問題、
  「ここを見てほしい」というレビュー観点、独自のチェックリストは渡さない。

## モデル

モデルはユーザーに明示してもらう。未指定ならセッションを作る前に質問し、現在のモデルや
デフォルトモデルを暗黙に使わない。

## セッションを作る

1. `yuru` skill の指示に従って接続と CLI を確認する。
2. 未作成の一意な結果ファイルのパスを予約し、一時ファイルへの書き込み後にそのパスへ rename
   してレビュー結果を返すよう依頼する。
3. 指定されたプロバイダと `--model` を使い、同じ worktree にレビューセッションを作る。
4. 結果が書かれるまで待ち、内容を読んでユーザーに返す。長時間返ってこなければ待機を打ち切り、
   その旨をユーザーに伝える。
