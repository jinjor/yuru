F41 Worktree Removal — 削除導線と確認ダイアログ

不要になった task worktree を左ペインから削除する機能の UI モックアップ。 主役は確認ダイアログ 3 種（通常 / open PR / force）、生きているプロセスがある時のブロック（メニュー段階）、そしてそれらをつなぐ判定フロー。

⚠ このモックの見方

  • 確認したいのは 削除の入口と 確認ダイアログの中身（何を消し / 何を残すかの伝え方）。文言・色・並びはここで詰める。
  • 左ペインのカードはダミー。既存実装の見た目に寄せてあるだけで、行間・影などは参考にしない。
  • ダイアログ内の文言は 英語（プロダクト UI に合わせる）。説明・注記は日本語。
  • 入口（︙メニュー）は提案。detail は「削除操作を選ぶ」としか決めていない。下の 提案セクション参照。

■ 確定仕様（detail 由来・ダイアログで崩さない）

  • 消えるのは worktree（作業ディレクトリ）と、この一覧の項目だけ。
  • branch は消さない。provider session 履歴も消さない（あとで resume できる）。primary session のひも付けだけが項目と一緒に消える。
  • force（--force）は通常削除とは別の明示確認。未コミット変更が消える / untracked file が消える、を判断材料にする。
  • dirty のファイル一覧・件数は出さない。必要なら Changes / Files / Git CLI で事前確認できる。
  • open PR は完全なブロックにしない。続行の明示意思があれば消せる。PR と branch は残る。誤削除の復帰は F42。
  • その worktree で生きているプロセスがある間は削除しない（active session が代表例）。先に停止が必要。最終判定は削除の直前に OS へ問い合わせる（停止と削除を 1 フローにまとめるのは初期実装では扱わない）。

■ 判定フロー（どのダイアログが出るか）

  1. 削除操作を選ぶ。
  2. active な session があれば → メニュー段階でブロック（ケース D）。確認ダイアログまで進まない。＝ detail step 2
  3. そうでなく open PR が分かっていれば → PR 警告付きの確認（ケース B）。なければ 通常の確認（ケース A）。＝ detail step 3
  4. 確認 → git worktree remove を実行。＝ detail step 4
  5. dirty で拒否されたら → force 確認（ケース C）。git の拒否を真実とし、こちらで dirty を先読みしない。＝ detail step 5
  6. 成功 → 一覧から項目を消す。＝ detail step 6–7
提案: 削除の入口（︙オーバーフローメニュー）
カードに primary session があるとクリックで session 選択に取られるため、削除はカード右上の ︙（ホバー / 選択時に表示）に逃がす。 押すとカードに固定された小さなメニュー（既存の action surface と同じ流儀）が開き、現状の項目は Remove worktree… の 1 つだけ。main worktree には ︙ を出さない（削除対象外）。
my-repo
main
terminal
feature/search-streaming
stream results as they arrive
fix/login-redirectOpen #128
guard the redirect param

右クリック（context menu）でも同じメニューを出せると速い。初期実装では ︙ だけでもよい。「…」は確認ダイアログが続くサイン。

ケース A: 通常削除（clean・PR なし・active session なし）
何が消えて何が残るかだけを淡々と。脅し要素はなし。
Remove worktree
feature/search-streaming ~/code/my-repo/.worktrees/search-streaming

Removes the worktree directory and its entry from this list. The branch and session history are kept — you can resume them later.

ケース B: open PR がある（ブロックせず、続行の明示意思を求める）
PR バッジを引き継いで「PR と branch は残る／Yuru 上の追跡だけ失う」を伝える。主ボタンは Remove anyway。
Remove worktree
fix/login-redirect Open #128
This worktree has an open pull request. Removing it won't touch the PR or the branch — but you'll lose the link to this work in Yuru.

Removes the worktree and its list entry. The PR, branch, and session history are kept.

PR 情報は provider（GitHub 等）から取れた時だけ使う。remote/local branch から PR を推測しない。

ケース C: force 削除（通常削除が dirty で拒否された後）
A / B で Remove を押した直後、git に拒否されて初めて出る 2 段目。強さはヘッダと文言で出し、ボタンは A / B と同じ danger（Force remove）。
Force remove worktree
feature/search-streaming ~/code/my-repo/.worktrees/search-streaming
This worktree has uncommitted work, so a normal remove was refused. Forcing will throw it away.

Uncommitted changes and untracked files will be discarded. The branch and session history are kept.

ファイル名・件数は出さない。中身を見たいなら Cancel して Changes / Files / Git CLI で確認できる。

ケース D: 生きているプロセスがある（削除させない・モーダルは出さない）
大半は active session で、Yuru がメニュー時点で把握している。だから専用モーダルは出さず、メニューの Remove worktree… を無効化して理由だけ添える。確認ダイアログまで進ませない。
my-repo
feature/search-streaming
working…
Stop the running session first

Yuru が知らない裏のプロセスやレースで削除直前に判明した時だけ、確認ダイアログの中身を同じ一文（Stop it first）に差し替える。専用の「Got it」モーダルは持たない。
