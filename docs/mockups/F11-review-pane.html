F11 Review — Changes 区間分割とレビューチェック (第 4 案)

設計 doc: docs/backlog-details/F11-review-from-base.md (この版の内容を反映済み)。 チェックの意味論 (base からこの内容までヨシ、表示は導出) は変わらない。 この版はレビューの印を最小化し、base を画面から消して自動解決だけにした。

前提 (確定済み)

  • Review の独立タブは作らない。区間は重複しない分割 (merge-base ↔ HEAD ↔ index ↔ 作業ツリー)。
  • チェックリストはファイルごとに 1 本。承認内容が commit されるとチェックは Committed 行に引き継がれる。
  • 並び順は Committed → Staged → Unstaged (変動するものが下)。Conflicted は例外で最上部。
  • Committed は既定で折りたたみ。進捗の分数 (4/12) は出さない。

この版で試している変更

  • レビュー済みの印はファイル名の取り消し線だけ。色・ディレクトリ・行数はそのまま残す (レビュー状態は変更の種類より重要度が低い。リストをレビュー中心のデザインにしない)。
  • チェックのトグルはリストから廃止。操作は diff パネルの Reviewed トグルだけ。 リストは表示専用なので取り消し線だけで足りる。
  • セクションヘッダのラベル左端を全セクションで縦に揃える (chevron は左余白に置く)。
  • dir は常に左寄せ (名前の真横)。F40 ヘッダと同じ「関心が同じものを隣接させる」配置。 省略はパス全体の後ろ省略 (あふれるのは dir 側)。
  • セクション名は Committed / Staged / Unstaged の三兄弟に。
  • base は fork point の推測 (全 local branch との merge-base 比較) で自動解決し、 解決結果の branch 名を Committed ヘッダに表示。切替 UI も作成時記録も持たない。
  • セクションヘッダの件数を削除 (合計 +/- は残す。リストを見れば分かるし、 総数は Changes タブの badge にある)。
  • diff ヘッダの範囲ラベルは Committed だけ (from main)。 Staged / Unstaged / Files から開いた diff は従来通りラベルなし。
