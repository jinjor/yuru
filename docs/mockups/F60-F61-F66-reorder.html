F60 / F61 / F66: 並び替え (drag & drop)

repo・worktree・primary session の 3 つを D&D で並び替える。 4 つの状態はどれもドラッグの途中の姿で、掴んでいる項目が浮き、隣が落ちる場所を空けてどいている。 設計の理由は docs/backlog-details/F60-F61-F66-ui-design.md にある。

このモックは実アプリの style.css とコンポーネントの DOM 構造をそのまま使っている。 色・寸法・クラス名は実物からのコピーなので、見えているものがそのまま実装の目標になる。 新しい CSS は .reorder-dragging (掴んでいる項目) と .reorder-shift (どく項目) の 2 つと、場所ごとの微調整だけ。ドラッグ中の transform の値は実際のレイアウトを計測して置いた もので、目分量ではない。青い番号バッジと、青い破線の帯 (自動スクロールの反応域) は注釈で、UI の一部ではない。

この設計の要点

  • 掴むのは項目そのもの。専用のハンドルは作らない。4px 動いたら並び替えが始まり、それ未満はクリック。
  • 隣がその場でどく。挿入線は出さない。空いたスロットがそのまま落ちる場所。
  • 入れ物をまたげない。掴んだ項目は自分の入れ物 (repo group / Sessions セクション / primary タブの並び) にクランプされる。
  • 並び替えは選択を変えない。タブを動かしても表示中のタブは変わらない。
  • タブの D&D はホームと同じ 1 本の並びへのショートカット。タブ列は独自の並びを持たない。
  • 端に近づいたら自動スクロール。スクロールするのは repo 一覧とホームだけ。タブ列は縮むのでスクロールしない。
ドラッグ中の見た目 掴んでいる項目 = 細い枠 + 影で浮かせる どく項目 = 140ms で 1 スロット分ずれる 空きスロット = 落ちる場所 (点線などは描かない)
状態 A: worktree を並び替え中 (F66)

f58-tab-polish のカードを掴んで、f59-provider-usage の直後へ運んでいるところ。 掴んだカードはポインタに追従し、下にいた 2 枚 (f60-61-66-order と i22-files-tree) が 1 スロット分ずれて場所を空けている。カードの高さは 62px と 52px が混ざっているが、ずれる量はどれも 「掴んだカードの高さ + gap」で同じ。

タブでの並び替えが全体の並びに与える影響 (説明図)
