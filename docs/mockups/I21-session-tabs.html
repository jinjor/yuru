I21: 複数 primary session とタブ UI

1 worktree に複数の primary session を認めた後の UI 構成。 シナリオ: worktree i21-primary-session で親 (Kimi) が子 (Codex ×2) に委譲している状態。

このモックは実アプリの style.css とコンポーネントの DOM 構造をそのまま使っている。 色・寸法・クラス名は実物からのコピーなので、見えているものがそのまま実装の目標になる。 新規 UI はタブ列だけで、それも既存コンポーネント (.panel-tab / .panel-header) の スタイル値に倣っている。実アプリの右端にある Explorer パネル (Changes / Files / Search) は、 タブとホームの説明に関係しないため省略した。青い番号バッジは注釈用で UI の一部ではない。

固定された仕様 (2026-08-09 更新)

  • タブ = live runtime の投影。runtime が生まれるとタブが増え、exit すると消える。空タブは作れない。
  • タブ列は Terminal ヘッダ行そのもの。見出し "Terminal" は消え、ブランチ名は右に残る。タブが増えたときは横スクロールせずタブ自体が縮む。
  • ホームタブは常に先頭で閉じられない。アイコンのみ。全 primary + suggested + 新規作成がここに並ぶ。
  • タブの × は runtime を kill するだけ (provider session は残りホームから resume 可)。detach はホームの各行の副操作。
  • カードの代表は先頭 primary 固定。子の状態でコロコロ変わらない。並びが変わるのは detach / re-promote のみ。
  • API (yuru CLI) からの session create はタブを増やすが選択を奪わない。
  • タブラベルは session preview の短縮。activity はテキストバッジではなくカードと同じドット表現で示す。
ドットの凡例 (カード・タブ・ホームで共通): active · working (点滅) active · waiting (点灯) inactive (減光) suggested (中抜き)
状態 A: runtime タブを選択中

親セッションのタブを表示中。子 2 つは裏で動いていて、タブのドットで分かる。 タブ列は Terminal ヘッダそのもの (右の Explorer の Changes / Files / Search と同じ形) で、 「TERMINAL」の見出しは無くなり、ブランチ名は右に残る。タブが増えたときは横スクロールせず タブ自体が縮む。全一覧は常にホームタブにあるので、縮んで読めなくなってもそこから辿れる。
