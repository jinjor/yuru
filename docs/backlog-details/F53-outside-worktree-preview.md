# F53 worktree 外の絶対ファイルパスをプレビューで開けるようにする

Last updated: 2026-07-25

## Goal

- ターミナルに出た `/tmp/...` のような worktree 外の絶対パスをクリックして、プレビューで開ける
- 対象は特定の種類のファイルに限らない

## Why

モックアップや調査用のファイルを worktree の外に作ることがある。リンクとしては検出されるが、
クリックしても何も起きないため、そのファイルを Yuru の中で確認できない。

## 現状

worktree 外のファイルは、種類を問わず 1 つも開けない。

- renderer: `SessionView` の `handleFileLinkActivate` (ターミナルのファイルリンクを踏んだ時の処理) が
  `resolveRepoFile` (worktree 相対パスへの解決) の `null` を見て、プレビュー選択自体を捨てている
- main: プレビューが使う解決処理はすべて worktree ルート基準で、外を指すパスは `null` / エラーになる

worktree 外のパスが入ってくる経路は今のところターミナルのリンクだけ。ファイルツリーもファイル検索も
worktree の中しか列挙しない。

## 決めること 1: worktree 外のパスの持ち方

プレビューの選択状態は worktree 相対パスとして持っている。ここに絶対パスが混ざるので、
両者をどう表すかを決める必要がある。

- 相対パスと絶対パスを 1 つの文字列に混在させるのか、種別を分けて持つのか
- main 側の解決処理 (ファイルの実体を読む・書く・差分を取る) をどう worktree ルート非依存にするか

## 決めること 2: 中身の読み方と diff

プレビューの中身は `getGitDiffDocument` が返す。無指定 scope では作業ツリーのファイルを読んだうえで
`isPathChanged` (git で変更の有無を見る関数) を呼ぶので、git の管理外にあるファイルは差分を出せない。

- 差分なしの単純表示にするのか、diff は対象外にするのか
- 編集モード (作業ツリーへの書き込み) を worktree 外にも許すのか

## 決めること 3: HTML プレビューで読み取りを許可する root

HTML プレビューだけは、他のファイルと違って選んだファイル 1 つでは完結しない。grant (プレビュー 1 回分の
読み取り許可) が **「読み取りを許可する root ディレクトリ」** を持ち、選んだ HTML とそこから相対参照される
CSS / JavaScript を root の内側からだけ読む、という境界でできているため、この root に何を選ぶかを決める
必要がある。

- entry が `/tmp/mock.html` のときに root を `/tmp` にすると、共有ディレクトリ全体が読み取り許可範囲になる
- ただしプレビューは CSP で `connect-src 'none'` / ポップアップなし / `form-action 'none'` なので、
  読んだ内容を外へ持ち出す経路はない。読めるのも CSS / JavaScript / 画像 / フォント / メディアとしてだけ
- 候補: entry ファイルの親ディレクトリを root にする / 開くときにディレクトリ単位で明示的に許可する

決めた root を渡すのは `service.resolveHtmlPreviewEntry` (プレビュー対象を root + 相対パスに解決する関数)
1 箇所で、`html-preview.ts` 側は root を渡されるだけなので変更は要らない。

## Non-goals

- HTML プレビューの隔離方針 (専用 protocol・sandbox iframe・CSP) 自体の変更
