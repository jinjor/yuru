# P21 UI をクリックした時のインタラクションを全体的に見直す

Last updated: 2026-07-19

## Goal

クリックできる UI (ボタン、カードなど) 全体で、操作した瞬間から結果が出るまでのフィードバックを揃える。
押した直後に何が起きているか分かり、待ちがある操作では待ちが見え、連打しても壊れないようにする。

## Why

P20 のレビューで、session start surface のボタンに「押しても無反応な時間」があることが分かった。
新規 Claude session は IPC が provider session id の解決を待ってから返るため、
クリック後 1〜2 秒、start surface が押せる見た目のまま無反応になる。
その間の再クリックは自然な反応だが、session の二重起動につながる。
暫定として「開始操作の実行中は後続の開始操作を無視する」ガードを SessionView に入れたが、
無視は無言で、ユーザーから見ると押しても何も起きないままになる。

同種の問題 (クリックへの応答がない・遅い・連打に弱い) はボタンに限らず、
カードなどクリックできる UI 全般に他にもありそう。個別に場当たりで直さず、全体を見てから直す。

## 進め方

1. まず洗い出しから。クリックできる UI を横断して、操作ごとに
   「押した直後に何が見えるか」「完了までの待ち時間」「連打・操作中の再操作の挙動」を確認する
2. 洗い出しの結果を見てから、直し方 (loading / disabled の出し方、待ち自体の解消など) を決める

## 既知の例

- 新規 Claude session 開始: 上記の 1〜2 秒の無反応。
  根本候補は Claude も Codex と同じ lazy attach にして IPC を即返すこと
  (待ちが消え、terminal に Claude の起動ログがそのまま見える)。
  次善は SessionView の表示状態を idle / starting / running の状態機械にして
  starting 中は disabled + spinner を出すこと。どちらかが入ったら暫定ガードは剥がす
