# F40 Edit Mode

`F40` は、ファイルを Yuru 内の埋め込みエディタで直接編集できるようにする機能。

Yuru は AI エージェントがほぼ全ての編集を行う前提で、エディタ自身は編集機能を持っていなかった。
ただ「エージェントが思った通りに書かなかったので人間が手で直す」という例外的な場面はあり、その都度外部エディタ (VSCode など) を開くのは往復が面倒。
編集を埋め込めればその往復が消える。

編集は**例外的な操作**である前提を崩さない。
この前提があるから、汎用エディタ (VSCode 等) のような全部盛りを避け、大幅に割り切れる。

## File view の 3 モード

ファイル表示をモードで切り替える。VSCode のフラットタブ方式は採らず、ファイルごとに次を切り替える。

- **閲覧モード** (現状)
  - Shiki ベースの読み取り専用表示。diff 表示もここに含む。
  - 既存の `DiffPreviewPanel` / `SourceViewer` 系をそのまま維持する。この機能では触らない。
- **編集モード** (この item)
  - CodeMirror で編集可能。
- **プレビューモード** (将来。現状は作らない)
  - Markdown / 画像のレンダリング表示。
  - プレビュー上で diff をどう見せるか (Markdown のインライン差分、画像の左右比較など) は **F40 のスコープ外**。ここでは作らない。

> **設計ガード**: ファイルビューのモードは `edit: boolean` のような二値にしない。**3 つ以上に拡張できる列挙 (union) として作る**。
> ただし **YAGNI**: 現状の member は `閲覧 | 編集` の 2 つだけ。プレビューはまだ作らないので**型にも加えない** (使われない variant を先に足さない)。
> 狙いは「将来 3 つ目を足せる形にしておく」ことであって、「最初から全部の選択肢を型に並べる」ことではない。`edit: boolean` だと拡張時に作り直しになるのを避けるのが目的。

バイナリ (画像含む) は **編集ボタンを disabled にするだけ**。閲覧モードは現状の表示 (「Binary preview is not available」等) のまま。フォールバックの仕組みは作らない。

CodeMirror と Shiki は独立した仕組みとして共存させる。閲覧＝Shiki、編集＝CodeMirror。
見た目はテーマを寄せて、モード切替時の違和感を抑える。
ハイライトを 1 系統に統一するために閲覧側 (Shiki) を CodeMirror に置き換える、という大きな書き換えはしない。今の要望には不要で、作り込んだ diff ビューアを壊すリスクが大きいため。

## ヘッダ表示

ファイル詳細パネルのヘッダは、左から **ファイル名 → ディレクトリ**、右クラスタに **モード切替アイコン → 変更行数 (+/−) → 閉じる**。

- 最重要情報の **ファイル名を主役**として左に出す。「CODE」のような見出しは廃止。uppercase にしない。ファイル名は省略しない。
- **ディレクトリはファイル名の真横**に小さく出す (関心が同じものを隣接させる)。質感は Changes ビューと揃える (subtle・mono・小さめ)。
- あふれるのはディレクトリ側で、**後ろ省略 (標準の `text-overflow: ellipsis`)**。Changes と同じで、賢い切り方 (前/中央省略) はしない。全パスはホバーで `title` に出す。
- モード切替は**アイコンのセグメント (コンパクト)**。モノレポの長いパスと両立させる。
- モックアップ: [docs/mockups/F40-edit-mode-modes.html](../mockups/F40-edit-mode-modes.html)（ヘッダのモード切替の検討用。本体の diff スタイルは参考にしない）。

## 編集モードの設計

### オートセーブ (明示保存は持たない)

編集モードはディスク上のファイルを直接編集し、変更は debounce してディスクへ書く。
「保存」という明示操作は持たず、**未保存状態という概念を作らない**。

設計判断の理由 (重要):
- 当初は明示保存 (Cmd+S) を想定したが、明示保存は「バッファとディスクが食い違う期間 = 未保存状態」を生む。
- dirty 表示・離脱時の扱い・破棄ルール・外部変更との衝突 (stale) 判定、これらの難所はすべて「未保存状態」が根本原因。
- オートセーブにすると食い違いの期間がゼロになり、上記の難所が**まとめて消える**。
- ディスクが single source of truth、worktree が作業の場、という Yuru の思想とも一致する。worktree の未コミット状態がドラフトそのもの。明示保存はむしろアプリ内に「ディスクと違う第二の真実」を持ち込んでいた。

特に Yuru は並行で複数セッションを回すため、ファイル編集中に別セッションへ離脱するのは日常。
「未保存のまま離脱したら消える」は致命的だが、オートセーブならその状態が原理的に存在しない。

実装上の注意:
- 書き込みは debounce する (1 キーごとに書かない)。file watcher と diff 再計算が暴れないようにする。

### 変更行マーク (ガター)

左ガターに変更行マークを出す (緑＝追加 / 赤＝削除)。

- 基準は閲覧モードの diff と同じく **Git の元内容**。
- 編集中は「元内容 vs 今エディタにある内容」で再計算してライブ更新する。
- diff 計算は既存の仕組み (元内容 vs 現在内容を `diff` で計算) を流用できる。

## 同時編集の割り切り

編集はエージェントの状態 (`working` / `waiting`) に関係なく常に可能。エージェントの状態で編集 UI を出し分けない。

- 当初は「悲観ロック＝`working` 中は編集ボタンを無効化」を検討したが、これは同時編集を防ぐための仕組みであり、本機能の「同時編集は対象外」という方針と矛盾する。オートセーブにした時点で、データ安全性のために `working` を見る必要もなくなった。よって `working` ゲートは持たない。
- Yuru は並行で複数セッションを回す前提なので、あるセッションが作業中でも人間がファイルを編集したい場面は普通にある。それを塞がない。
- 「人間が編集中に、別経路でエージェントが同じファイルを書く」は**低確率ケースとして対象外**。起きたら最後に書いた方が残る (last-write)。stale チェックや reconcile ダイアログは作らない。

## 捨てる / やり直す手段

明示保存が無いので、「捨てる」は Cmd+S の所有ではなく操作として用意する。

- **編集中のやり直し** → エディタの undo。頻度が高いケースはこれでカバー。
- **編集を確定的に捨てる / hunk 単位で戻す** → Git の変更破棄。
  - これは今 Yuru に無いので作る必要がある。
  - diff の hunk は既に計算しているので、hunk 単位 discard は後から無理なく乗る。
  - **最初の編集モードには必須ではない**。undo で回しながら作り、苦しくなったら Git discard (まず全体、必要なら hunk 単位) を足す。

## ライブラリ選定

編集モードは **CodeMirror 6** を使う。

- Monaco は強力だが重く、Vite の worker セットアップが面倒で、独自のハイライトを持つ。「たまに編集」には過剰。
- CodeMirror は「部品を組む」思想で、最小依存の方針に合う。ガターも編集も標準拡張で組める。
- ハイライトは Shiki に拘らない (元々 read-only / 軽量前提で Shiki を選んだだけ)。CodeMirror 側の標準で良い。

## 実装前に確認すること

- CodeMirror 6 の編集モードとガター拡張の具体挙動 (推測で進めない)。
- オートセーブ時に file watcher / diff 再計算が暴れないか、debounce の設計。

## 対象外 (割り切り)

- 閲覧 (Shiki) 側を CodeMirror に統一する書き換え。
- 未保存状態・dirty 表示・離脱時の保存確認ダイアログ・stale 判定・reconcile ダイアログ。
- 「人間が編集中にエージェントが同じファイルを書く」競合の能動的なハンドリング。
- 最初の段階での Git discard (将来、苦しければ追加)。

## Acceptance

- ファイル表示を閲覧 / 編集 / プレビューでファイルごとに切り替えられる。
- 編集モードでファイルを編集すると、debounce 後にディスクへ書かれ、diff に反映される。
- 編集モードの左ガターに変更行マーク (追加/削除) が出て、編集中にライブ更新される。
- 編集はエージェントの状態 (`working` / `waiting`) に関係なく開ける。
- 別セッションへ離脱しても編集内容が失われない (オートセーブのため未保存状態が存在しない)。
